# Native Messaging Protocol v1

Canonical Host: `com.kwel.bridge`. The compatibility registration `com.kwel.alfred` points to the same Rust executable so existing Kwel extensions keep working. No search-engine or extension changes are required.

The executable accepts the Chrome-supplied `chrome-extension://<extension-id>/` origin as its first argument. Both manifests and Host origin validation admit exactly the configured published Kwel extension ID. Developer-loaded extensions with a different ID need a separate local build; IDs are never discovered and trusted automatically.

## Transport and limits

Use Chrome Native Messaging: a four-byte **little-endian** unsigned byte length followed by one UTF-8 JSON value. All supported CPU targets are little-endian. Length is 1–1,000,000 bytes in both directions. Empty, oversized, truncated, invalid UTF-8, duplicate-field, unknown-field and trailing-JSON inputs are rejected. `stdout` contains framed protocol messages only; diagnostics are static messages on `stderr`.

The [JSON Schema](schemas/native-messaging-v1.schema.json) and Rust's type-specific Native wire representation define the fields. Public Local Client routing and internal migration messages are separate protocols: `profileId` is not a search/open-page Native field. Unknown fields, including fields belonging to another Native type, are rejected.

**UTF-16 code units are the normative string length**, not UTF-8 bytes, Unicode code points or grapheme clusters: query ≤200, request ID 1–100, profile label ≤64 without CR/LF. Empty query, 200 Japanese BMP characters and 100 astral emoji are valid; 201 Japanese characters and 101 emoji are invalid. A supplementary scalar (U+10000–U+10FFFF), including a JSON-escaped surrogate pair, counts as two units. Mixed strings use the same sum. Unpaired surrogate escapes are rejected; strings contain Unicode scalar values. Profile IDs and issued openRefs use hyphenated RFC-variant UUIDs, versions 1–8, retaining the Go validator's accepted range.

JSON Schema's `maxLength` counts Unicode code points. A schema validator alone is insufficient unless it implements the normative `x-utf16-maxLength` extension and rejects unpaired surrogates. Rust uses `encode_utf16().count()`; JavaScript uses `.length` on well-formed strings. Apply the limit before allocating or forwarding a request.

## Messages

All messages contain `v: 1` and `type`. Required fields are present even when empty: search has `query: ""` and an empty search-result has `items: []`. Control messages such as hello-ack/ping never acquire query. Optional profileLabel/message may be omitted when empty.

| Direction | Type | Fields |
| --- | --- | --- |
| Extension → Host | `hello` | `profileId`, optional `profileLabel` |
| Host → Extension | `hello-ack` | none |
| Host → Extension | `ping` | none |
| Extension → Host | `pong` | none |
| Host → Extension | `search` | `requestId`, required `query` (empty string allowed), optional `limit` (1–100, default 20); Host emits an explicit limit |
| Extension → Host | `search-result` | matching `requestId`, `items`, required `hasMore` |
| Host → Extension | `open-page` | `requestId`, `openRef` |
| Extension → Host | `open-result` | matching `requestId`, `ok: true` |
| Extension → Host | `error` | `requestId` string when correlated; null or omitted when uncorrelated, `code`, optional `message` |

Each result item has `title`, `url`, `domain`, and `openRef`. URLs must be HTTP(S) with a hostname. Empty result arrays are accepted; result order is never changed. Error codes preserve `BAD_REQUEST`, `INVALID_REQUEST`, `INCOMPATIBLE_VERSION`, `NOT_READY`, `RESULT_EXPIRED`, `OPEN_FAILED`, `SEARCH_FAILED`, `PROFILE_CONFLICT`, `HOST_NOT_FOUND`, `DISCONNECTED`, `TIMEOUT`, and `PERMISSION_REQUIRED`.

Native open-page carries only an opaque nonempty openRef string of at most 100 UTF-16 units. It is never interpreted as a URL. The Host sends only issued UUID references; the public Local Client validator still requires a UUID and the session must own an unexpired, unused reference. Native validation never grants public clients arbitrary URL opening.

## Session behavior

Hello must arrive within five seconds. A profile owns one public IPC endpoint and one authenticated internal coordination endpoint. A duplicate profile receives no hello-ack; the established session rejects new and pending requests with `PROFILE_CONFLICT` while the duplicate connection overlaps. Coordination leases expire after the rejected five-second handshake window, allowing recovery after a duplicate process crashes.

Native request IDs are generated by the Host. Responses are correlated to the originating local request and validated before delivery. At most 32 requests are pending; searches/opens time out after 12 seconds. Probe ping/pong has a two-second deadline; waiting for another probe is also bounded to two seconds. Disconnection cancels pending work.

Only error accepts a null/absent requestId. Successful search-result/open-result require a nonempty ID of at most 100 UTF-16 units. A valid correlated error completes only that exact pending ID; the connection remains usable. A valid uncorrelated error is ignored: it is never assigned to another pending request, does not cancel it, does not extend its deadline and does not disconnect an otherwise valid session. Incompatible envelope versions, malformed frames/JSON, unknown fields/types, wrong-direction messages and malformed success responses still fail closed and cancel the session's pending work. No search data or IDs are logged for an uncorrelated notice.

openRefs expire after five minutes, are consumed once before opening, and are scoped to the Native connection. The Host retains at most 500 opaque references; Kwel continues to perform its own expiration, single-use, connection and search-availability checks. Clients cannot submit a URL to open.

## Compatibility evidence

The shared [Native-only fixture](../crates/kwel-protocol/tests/fixtures/native-messaging-v1.json) contains 65 examples from Kwel PR #211 at `1ac876f8859e9f95100d7fcae4df86b3d7af890c`. Its [provenance](../crates/kwel-protocol/tests/fixtures/native-messaging-v1.source.json) pins the parser/fixture hashes. Rust validates every example; `scripts/test-kwel-parser.cjs` also executes that unmodified Kwel parser and builders, then passes actual Rust-encoded messages back through the Kwel parser. Nine additional well-formed Unicode boundary cases run on both implementations. This is codec conformance, not Chrome E2E; see [real Chrome verification](chrome-e2e.md).

The original 81 [Go-reference cases](../crates/kwel-protocol/tests/fixtures/go-v1.json) remain byte-for-byte historical material from `ea1bcce918f88c0c6efb6a81353db2001d778709`. A test-only historical codec snapshot preserves every original verdict and normalized JSON value, including its obsolete omission/routing behavior. It calls the maintained validation helpers and public Local Client validator for routed open requests. The production Native codec never uses that snapshot: the separate 65-case Native suite enforces required empty query/items, optional Native limit default 20, and Native-only field sets. No Go toolchain is required.

Rust strings reject unpaired surrogate escapes. JavaScript Native validators must likewise reject lone surrogates while counting a well-formed pair as two units; the native request-ID recovery helper must not correlate malformed IDs. Profile-label normalization may replace malformed units before truncating without splitting a valid pair. The general Kwel SEARCH_PAGES API is outside these Native-boundary rules.
