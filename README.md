# Kwel for Alfred

Search your Chrome browsing history from Alfred using [Kwel](https://kwel.ryu.zone). Choose a result and press Return to open the page in the Chrome profile that searched it.

## Requirements

- macOS and Alfred 5 with Powerpack
- Google Chrome
- A Kwel build with Alfred Integration and Native Messaging support

The current distribution configuration is a development candidate for an unpacked Kwel build. It is not a general release for every Kwel installation. See [Development](#development) for the build configuration.

## Setup

1. Open Kwel Settings in the Chrome profile you want to search. Enable **Alfred Integration** and approve Chrome's permission prompt if shown.
2. Copy the **Profile ID** generated by Kwel.
3. Import `Kwel.alfredworkflow`. Open **Configure Workflow…** and paste the ID into **Kwel Profile ID** (`KWEL_PROFILE_ID`).
4. In Alfred Preferences, open **Features → Default Results → Setup fallback searches** and add **Search Kwel**. Put it first if you want it to be the default fallback.

The first explicit **Search Kwel** invocation registers the bundled Native Messaging host if needed. Importing the Workflow alone does not install the host. After a Workflow update, the same search entry updates the installed Bridge.

Kwel's automatic reconnection can take time. If it remains disconnected after the host is registered, turn **Alfred Integration** off and on in Kwel Settings, then retry. Keep the same Profile ID.

## Search

1. Open Alfred and type a query, such as `github actions` or `日本語検索`.
2. Choose **Search Kwel** and press Return.
3. Select a page and press Return to open it in Chrome.

No `kwel` keyword, additional global hotkey, or profile selection screen is needed. To search another Chrome profile, change **Kwel Profile ID** in Workflow Configuration. The next search uses that ID.

Alfred controls when fallback candidates appear. **Intelligently show fallbacks at the end of results** does not guarantee that Kwel is always visible. With Search Kwel first in the fallback list, Alfred's default **Control + Return** action invokes that fallback from normal results. See [Alfred's fallback documentation](https://www.alfredapp.com/help/features/default-results/fallback-searches/) and [action modifiers](https://www.alfredapp.com/blog/tips-and-tricks/action-modifiers-quick-alternative-actions/).

After Kwel confirms that a page has opened, the Workflow activates Google Chrome. Switching to Chrome's Space follows the macOS Mission Control setting for switching to a Space with open windows for an application. Activation is at the application level; the destination with multiple Chrome windows in different Spaces has not been verified.

## Search and connection behavior

- Only the configured Profile ID's connection is used. A missing, disconnected, or duplicate connection produces one disabled notice.
- Kwel performs the search and supplies the ranking. Alfred requests up to 20 results, disables its own filtering, sets `skipknowledge: true`, and omits result `uid` values.
- Each result carries Kwel's opaque `openRef` and its search-time Profile ID. Changing Configuration afterward cannot redirect that result to another profile.
- Native Messaging uses `com.kwel.alfred`, an exact extension origin, and private per-profile Unix sockets. The socket directory has mode 0700 and sockets have mode 0600.
- User Configuration stays in Alfred's `prefs.plist`. It is not included in the package or committed to this repository.

## Development

Building requires macOS, Go 1.22 or later, Python 3, and the macOS developer tools. The project has no third-party Go dependencies.

Build a universal arm64/x86_64 Workflow package:

```sh
bash scripts/package-workflow.sh
```

The package is written to `dist/Kwel.alfredworkflow`. You can also pass an absolute output path as the first argument.

Run the checks:

```sh
bash scripts/verify.sh
```

This runs Go vet, Go race tests, safe argv checks, the universal build, and package verification. The default output stays inside `dist/`.

Distribution settings are in `config/distribution.json`. Maintainers must set `chromeExtensionId` to the intended Kwel distribution's extension ID and confirm that the build supports the existing Native Messaging protocol. This extension ID is separate from the per-user Profile ID entered in Workflow Configuration.

The development Bridge is not Developer ID signed or notarized. Signing and release checks are available through the existing build script's `KWEL_CODE_SIGN_IDENTITY` and `KWEL_RELEASE` environment variables.

## Verification scope

Automated checks cover the required Profile ID Configuration field, workflow connections, JSON ordering, Native Host handshake and routing, concurrent and stale responses, expired open references, safe argument passing, activation ordering, archive contents, and both macOS binary architectures.

Live Alfred import/update behavior, Chrome Native Messaging, equality with live Kwel results, real page opening, and Spaces switching are outside these automated checks. Local user feedback confirmed search with the matching development build; Spaces activation remains unverified on device.
